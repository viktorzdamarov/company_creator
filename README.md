# Adrobot

Сервис для трекера Keitaro (10.3.x): создание кампаний по шаблону и редактор офферов в существующих кампаниях.

Стек: FastAPI, SQLAlchemy 2.0, Alembic, фронт на HTML + jQuery.

> Статус: создание кампаний и редактор офферов (черновик → Push, Cancel, Bring back, закрепление долей) с веб-интерфейсом.

## Веб-интерфейс

После запуска (`uvicorn app.main:app --reload`) откройте http://127.0.0.1:8000:

- **New campaign** (`/create`) — форма по макету ТЗ: Name, Geo (`MX,AU,RO`), Offer с автокомплитом, кнопка Create.
  Галочка «Предпросмотр (dry run)» показывает, что будет создано, ничего не отправляя в Keitaro.
  После создания — ID, tracking URL (кнопка «копировать»), потоки и ссылка в редактор.
- **Editor** (`/edit`, `/edit/{id}`) — поиск кампании по ID или названию, кнопка **Fetch streams**.
  Изменения копятся локально (поток жёлтый) и уходят в Keitaro только по **Push**; **Cancel** отменяет их.
  Удалённый оффер серый (0%), его можно вернуть (**Bring back**); долю оффера можно закрепить (📌).

Фронт — Jinja2-шаблоны + jQuery 3.7.1 (`app/templates`, `app/static`), данные берутся из JSON API.

## API

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/offers?q=` | поиск офферов по ID или части названия (автокомплит) |
| `POST` | `/api/campaigns` | создать кампанию: `{"name": "...", "geo": "MX,AU,RO", "offer_id": 18813}` |
| `POST` | `/api/campaigns?dry_run=true` | то же без создания: показывает, что будет отправлено в Keitaro |

Создаваемая кампания:
- **Flow 1** — фильтр «Страны принимать = GEO» → редирект на https://google.com
- **Flow 2** — весь остальной трафик → выбранный оффер (100%)
- домен, группа и источник — из `KEITARO_DEFAULT_*` в `.env`; ротация «По позиции», CPC

Ответ содержит ID кампании, tracking URL и созданные потоки. Ошибки:
`422` — неверный GEO/имя или Keitaro отклонил данные; `404` — оффер не найден; `409` — кампания с таким именем уже есть;
`502/503/504` — проблемы с Keitaro (ключ, недоступность, таймаут). Если поток не создался, кампания удаляется (откат).
Все операции пишутся в таблицу `operation_logs`.

### Редактор

Редактор хранит локальную копию потоков и офферов в БД (таблицы `editor_*`). Все правки сначала делаются
в ней и попадают в Keitaro только после Push.

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/campaigns?q=` | список кампаний Keitaro, поиск по ID или части имени |
| `POST` | `/api/campaigns/{id}/fetch` | **Fetch streams**: загрузить потоки из Keitaro и слить с локальной копией |
| `GET` | `/api/campaigns/{id}` | локальная копия: потоки, офферы с %, статусы, Клики / Уник. / Боты (`404`, если ещё не загружена) |
| `POST` | `/api/campaigns/{id}/streams/{stream_id}/offers` | добавить оффер в черновик `{"offer_id": 18813}` |
| `DELETE` | `/api/campaigns/{id}/streams/{stream_id}/offers/{offer_id}` | удалить оффер из черновика (серый, 0%) |
| `POST` | `.../offers/{offer_id}/bring-back` | вернуть удалённый оффер |
| `PUT` | `.../offers/{offer_id}/pin` | закрепить / открепить долю `{"pinned": true}` |
| `POST` | `.../streams/{stream_id}/push` | **Push**: опубликовать поток в Keitaro |
| `POST` | `.../streams/{stream_id}/cancel` | **Cancel**: отменить неопубликованные изменения потока |

Правила редактора (по видео заказчика):
- **Fetch streams** загружает потоки. Поток без офферов показывается просто как поток, без фильтров и редиректа;
- **добавление/удаление** меняет только локальную копию: поток становится жёлтым («не опубликован»), в Keitaro
  ничего не уходит; доли пересчитываются сразу;
- статусы оффера: `active` (в Keitaro), `new` (добавлен, не опубликован), `removing` (удалён, но ещё в Keitaro),
  `removed` (архив: удалён из Keitaro, остаётся у нас);
- **Push** отправляет офферы и доли потока, перечитывает поток из Keitaro и сверяет результат; удалённые офферы
  уходят из Keitaro, но остаются в архиве; нельзя опубликовать поток без офферов (`422`) или с суммой долей не 100% (`422`);
- **Cancel** убирает добавленные и не опубликованные офферы, отменяет удаления и возвращает доли;
- **Bring back** возвращает оффер из архива (или отменяет ещё не опубликованное удаление);
- **повторный Fetch**: оффер, удалённый в самом Keitaro, не пропадает, а становится серым `removed`;
  неопубликованные локальные изменения сохраняются;
- **доли**: по умолчанию поровну (100/N, остаток по 1% первым офферам: 3 → 34/33/33). Закреплённая доля не меняется,
  остальные офферы делят остаток поровну (закреплён 25% из 4 → остальные 25/25/25; один удалён → 25/38/37). Закреплённые доли
  не могут давать больше 100% или не оставлять места незакреплённым офферам (`422`, ничего не меняется);
- офферы редактируются только в потоках с офферами (`422` для остальных); один оффер дважды в поток — `409`;
- все действия пишутся в `operation_logs`.

## Требования
- Python 3.11+
- Доступ к Keitaro и API-ключ (Keitaro → Профиль → API ключи)

## Установка

```bash
python -m venv .venv
# Windows:  .venv\Scripts\activate
# Linux/Mac: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env    # затем заполните KEITARO_URL и KEITARO_API_KEY
```

## Миграции

```bash
alembic upgrade head      # создать/обновить схему БД
alembic downgrade base    # откатить все миграции
```

По умолчанию используется SQLite (`adrobot.db`); для Postgres задайте `DATABASE_URL`.

## Запуск

```bash
uvicorn app.main:app --reload
```

- Healthcheck: http://127.0.0.1:8000/health
- Swagger: http://127.0.0.1:8000/docs

## DEMO-режим

Позволяет попробовать всё приложение (создание кампаний и редактор) без настоящего Keitaro: вместо него работает
встроенная имитация с вымышленными данными. Ключ и адрес Keitaro не нужны.

```bash
# Windows PowerShell:  $env:DEMO_MODE="true"; uvicorn app.main:app --port 8000
DEMO_MODE=true uvicorn app.main:app --port 8000     # или DEMO_MODE=true в .env
```

- 5 вымышленных офферов лежат в [app/keitaro/demo_offers.json](app/keitaro/demo_offers.json) (ID 9001–9005);
  их можно править, список читается при создании демо-данных;
- при первом запуске создаются кампании `demo_campaign_001` (1 оффер) и `demo_campaign_multi` (3 оффера);
  новые кампании тоже можно создавать через форму;
- Клики / Уник. / Боты в демо выдуманные, но стабильные;
- состояние (кампании и потоки «в Keitaro») хранится в `DEMO_STATE_FILE` (по умолчанию `demo_state.json`);
  удалите файл, чтобы начать заново (и сбросьте локальную БД редактора: удалите `adrobot.db` и выполните `alembic upgrade head`);
- вверху страницы видна жёлтая плашка DEMO.

Сценарий редактора в браузере (add → Push → Pin → Remove → Bring back → Cancel), нужен запущенный демо-сервер:
`cd tests/e2e && npm install && ADROBOT_URL=http://127.0.0.1:8000 npm run demo`.

## Тесты

```bash
pytest
```

Проверка подключения к реальному Keitaro (только чтение, ничего не меняет):

```bash
python -m scripts.keitaro_smoke            # справочники, офферы, дефолты из .env
python -m scripts.keitaro_smoke 215521     # + потоки и статистика кампании
```

Форматы запросов/ответов Keitaro API: [docs/keitaro_api_notes.md](docs/keitaro_api_notes.md).

Браузерный smoke-тест интерфейса (нужны Node.js 18+ и Edge/Chrome; в Keitaro ничего не меняет —
создание в режиме dry-run, редактор работает с локальным черновиком и не нажимает Push). Нужна кампания
с потоком офферов; её имя задаётся в `ADROBOT_CAMPAIGN` (по умолчанию ищет `adrobot-test`).

```bash
uvicorn app.main:app --port 8000          # в отдельном терминале
cd tests/e2e && npm install
npm test                                   # BROWSER_PATH=... для Chrome, ADROBOT_URL=... для другого адреса
```

## Переменные окружения

| Переменная | Описание |
|---|---|
| `KEITARO_URL` | адрес трекера |
| `KEITARO_API_KEY` | ключ Admin API |
| `KEITARO_DEFAULT_DOMAIN` / `_GROUP` / `_SOURCE` | домен, группа и источник для новых кампаний |
| `KEITARO_TIMEOUT` / `KEITARO_MAX_RETRIES` / `KEITARO_RETRY_BACKOFF` | таймаут запроса, число повторов при 429/5xx/сетевых ошибках, начальная пауза |
| `DATABASE_URL` | строка подключения SQLAlchemy |
| `LOG_LEVEL` | уровень логирования |
